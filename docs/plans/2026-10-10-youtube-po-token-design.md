# YouTube 高画质 PO Token 修复设计

## 目标

解决同一 Cookies 下部分视频只返回 360p 的问题。Cookies 继续承担登录和内容权限验证，PO Token Provider 按视频生成 YouTube 播放请求需要的短期令牌。解析、频道扫描和所有下载路径统一复用 yt-dlp 基础命令。

## 架构

项目固定使用版本匹配的 `bgutil-ytdlp-pot-provider` 插件与本地 BgUtils HTTP 服务。跨平台安装脚本从上游版本标签下载源码，在 `.runtime` 中安装依赖并编译。Channel Keeper 启动时在 `127.0.0.1:4416` 启动服务，退出时关闭自己创建的进程；若端口上已有兼容服务则直接复用。令牌端口不监听局域网地址。

上游服务的标准输出可能包含生成的短期令牌，因此进程输出直接丢弃，不写入应用日志或磁盘。

yt-dlp 使用 `mweb,tv,web_safari` 播放器客户端组合。插件自动与本地服务通信，按视频和会话生成所需令牌。系统不启用 `formats=missing_pot`，避免向用户展示实际会返回 403 的虚假可用格式。

## 错误处理与界面

运行环境增加令牌插件和服务状态。插件、Node.js 22 或已编译服务缺失时，程序仍可运行，但诊断明确标记缺失。单条视频最高只解析到 360p 时，根据服务状态分别提示安装问题或视频权限、处理状态等站点侧限制。

## 验证

单元测试覆盖命令参数、服务生命周期、诊断状态和 360p 提示。安装脚本验证归档路径安全、Node.js 主版本和编译产物。完整测试继续覆盖下载队列、Cookies 隔离、格式选择和本地媒体集成。
